Can SQRA fix the issues that Essentials shows users?

Essentials is the rule set that decides what a new user sees. SQRA is the agent that auto-fixes issues. This board answers one thing: of the 3,694 rules in Essentials, how many can SQRA actually fix?

Coverage in the 5 languages SQRA knows
Java, JavaScript, TypeScript, Python, Secrets. Of 1,516 Essentials rules there, SQRA fixes 1,512. Just 4 are blocked (all “cognitive complexity”).

Essentials rules SQRA can’t touch
They live in 45 other languages — C++, C#, Go, PHP, IaC and more — that SQRA doesn’t support yet. This is the whole gap.

The takeaway

SQRA’s limit is which languages it supports, not which rules are too hard. Inside its languages it fixes almost everything Essentials surfaces; the 59% it misses is entirely other languages.

How this was computed. Essentials membership pulled live from SonarCloud (default Sonar way profiles) — a rule is kept if any Clean Code impact is Security (any), Reliability ≥ Medium, or Maintainability ≥ High. SQRA-fixable = the 5 supported languages minus the published blocklist (Java 7, JS 5, TS 5, Python 4, Secrets 0). C# blocklist rules in the docs are ignored because C# isn’t an SQRA language yet.
Both lists are derived, not fixed — they move as rules, impacts, or the blocklist change. Snapshot taken today.
